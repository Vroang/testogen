- ЧАСТЬ 2 — Room 9 → 10 (MIGRATION_9_10):
  - questions: + cloudId (uuid в облаке), + syncStatus
    (старым вопросам — pending_upload, чтобы они ушли в облако
    при первой синхронизации);
  - replacement_reasons: + cloudId, + syncStatus (то же);
  - pending_deletes: + type (textbook/question/reason) и
    cloudId. Существующие данные сохраняются.
- ЧАСТЬ 3 — QuestionSyncRepository (local-first, как шаг 30):
  - syncAll: очередь удалений → ожидающие вопросы → ожидающие
    причины; запускается при старте приложения и при открытии
    вкладки «Файл»;
  - вопросы/причины со статусом pending_upload уходят в
    Supabase через upsert (по cloudId — идемпотентно); успех →
    synced; нет сети → остаётся pending;
  - удаления: локально сразу; если у записи был cloudId —
    в очередь pending_deletes, фоном удаляется из облака;
  - очистка банка («Удалить ВСЕ вопросы»), очистка причин
    (сжатие инструкций, «Очистить», сброс) — тоже ставят
    очередь на все облачные записи;
  - редактирование вопроса помечает его pending_upload и
    сразу догоняет в облако.
- TextbookRepository.syncPendingDeletes больше не трогает
  записи чужих типов (только textbook).
- Настройки: блок «Синхронизация с облаком» теперь считает
