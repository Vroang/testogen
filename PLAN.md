## Этап 2 — нейросеть и качество вопросов ✅
- DeepSeek напрямую (`deepseek-flash` = V4.1-Flash, `thinking: disabled`, `response_format: json_object`) → при ошибке OpenRouter (`deepseek/deepseek-v4.1-flash-1017`, reasoning выключен). Цены и модель сверены с api-docs.deepseek.com 2026-10-23 (`ai/Pricing.kt`, пиковые часы ×2).
- Неизменный system-промпт (`ai/Prompts.kt`) → кэш DeepSeek срабатывает со второй порции. Всё переменное (правила, тема, класс, «уже есть: вопрос → ответ») — в сообщении пользователя.
- Модель возвращает вопрос, верный ответ, 3 неверных, сложность, пояснение; код перемешивает варианты, сохраняет сложность модели.
- Проверки в коде (`ai/QuestionQuality.kt`, юнит-тесты): 4 разных варианта, без «все перечисленное», ответ не подсказан в вопросе, верный не заметно длиннее; отсев повторов — тот же верный ответ в теме или почти тот же текст.
- Порции по 10 (+3 запасных), max_tokens с запасом, при обрыве порция уменьшается; недостающая сложность добирается в следующих порциях.
- Второй проход-рецензент (по умолчанию включён, переключатель на экране): ~$0,0003 на порцию, отсекает 1–2 сомнительных вопроса из 13.
- Фоновая генерация: WorkManager + foreground-уведомление (dataSync); задание в таблице `generation_jobs`; переживает сворачивание и принудительную остановку (продолжает с места); «Остановить» обрывает и HTTP-запрос.
- Экраны: «Вопросы по теме» (класс, количество, сложность, перепроверка, оценка стоимости), ход генерации (этапы, плавный прогресс, скелетоны, появляющиеся вопросы), вопросы темы (удаление с «Вернуть»), ручной ввод/правка (тема не теряется), правила «Чего не делать» (только дополняются; `RulesUpdater` для причин замен — вызов появится на этапе 4), проверка ключа с балансом.
- Проверено на телефоне: 4 темы, 100 вопросов, всего ≈ $0,01 (≈ $0,0001 за вопрос с перепроверкой); прокрутка 50 карточек — 0,5 % рывков.
- Debug-сборка принимает `--es debug_topic "Тема"` (adb не вводит кириллицу).

## Этап 3 — учебники ✅
- Импорт PDF/DOCX/TXT в фоне (WorkManager, задание kind=import), файл копируется к себе потоком; PDF — pdfbox-android постранично с `MemoryUsageSetting.setupTempFileOnly()`. Учебник 243 стр./41 МБ: ≈25 с в release-подобной сборке, ≈45–60 с в debug.
- `TextbookAnalyzer` (чистый Kotlin): основной размер шрифта; колонтитулы и номера страниц из верхней/нижней полосы выкидываются, номер страницы книги запоминается (pdf ≠ книга); переносы склеиваются; абзац, прерванный врезкой/страницей, доклеивается; параграфы по значку «§ N»/«§ N–M» (любые тире) + крупный заголовок на той же странице; главы «Глава I. …» с титульной страницей; врезки (мелкий шрифт), подзаголовки, «Ключевые понятия», блоки заданий («Проверяем себя», «Исследуем»…), доп. материалы; задания к главам, заключение, словарь (89 терминов) — отдельными разделами; сверка с оглавлением (заголовки берутся из него, расхождения — предупреждения).
- Результат на учебнике из examples/: 5 глав, 19 параграфов (в т. ч. § 2–3, 6–7, 13–14, 21–22), все страницы совпали с оглавлением, предупреждений нет. Тест `TextbookAnalyzerTest` — на выгрузках PyMuPDF и PDFBox (tools/).
- PDF без текста → статус «scan», понятное сообщение, распознавание не делается.
- Экраны: список учебников с прогрессом импорта; структура (главы/параграфы/страницы, число вопросов) с правкой (название, номер, «для вопросов», соединить со следующим; разделить — долгим нажатием на абзац в чтении); поиск по учебнику; чтение (ключевые понятия, врезки, задания, отметки страниц, крупный шрифт); оригинальная страница PDF (PdfRenderer, масштаб); создание вопросов по выбранным параграфам.
- Генерация по учебнику: текст параграфа первым в сообщении (кэш DeepSeek: 2-я порция 9344 из 10023 токенов из кэша), вопросы учебника и определения из словаря как подсказка; длинный параграф делится на части ≤28 тыс. символов по подзаголовкам; вопросы делятся между параграфами по объёму; цитата-источник ищется в тексте (`QuoteMatcher`, нестрого), вопрос без найденной цитаты отбраковывается; позиция хранится → «Откуда вопрос» открывает параграф с подсветкой.
- Промпт дополнен правилами для обществознания/права/экономики (определения, признаки, классификации, примеры; без мнений; без «спорных пар»), рецензент ловит спорные пары и проверяет опору на цитату. Обороты «согласно тексту» вычищаются кодом.
- Доработки по ходу: цены везде в $ и ₽ (курс в настройках, по умолчанию 103); переход на OpenRouter только при недоступности DeepSeek (сеть, 5xx, таймаут) или нехватке денег.
- Проверено на телефоне: импорт, структура, чтение, страница PDF, поиск; генерация § 6–7 (20 вопросов, $0,0045, темы совпадают с examples/Тест.docx), § 11 + § 19 (20 вопросов, $0,0052); «Откуда вопрос»; плавность структуры и чтения — 0 % рывков.

## Этап 4 — сборка теста ✅
- `TestBuilder` (чистый Kotlin, тесты): без повторов между вариантами — пропорциональный отбор по сложности и темам и раздача «по кругу» (в каждом варианте похожая смесь); с повторами — равномерное использование, внутри варианта повторов нет; в варианте от лёгких к сложным; 40×40 < 300 мс.
- Экран «Новый тест»: темы из банка (несколько), варианты 1–40, вопросов 1–40, сложность; сколько подходящих и сколько нужно; если не хватает — «Создать N» с ценой (по учебнику для тем из параграфов, иначе по теме; прогресс прямо на экране) или «Разрешить повторы».
- Черновик в базе (`tests`, `test_items`): экран теста с вариантами, проверка ответов, «Заменить» (причина: готовые + свои слова; новый вопрос от нейросети с учётом причины — сложность сдвигается для «слишком сложный/лёгкий», для учебника — по тексту параграфа с цитатой; или неиспользованный из банка), «Изменить», «Откуда вопрос», «Удалить» с «Вернуть», переименовать/удалить тест.
- Причины замен сохраняются; когда новых ≥ 5 — правила «Чего не делать» тихо дополняются.
- Проверено на телефоне: тест 2×5 по § 6–7; замена «Неоднозначный» → новый вопрос с цитатой ($0,0033, ~12 с); удаление и возврат; тест 40×30 с повторами.
- Начало запроса при замене совпадает с генерацией — текст параграфа из кэша.

## Этап 5 — Word ✅
- `DocxBuilder`: собственный генератор .docx (XML + zip, без Apache POI); Times New Roman, A4, «Вариант N», вопросы «N. …» жирным, ответы «1.–4.» с висячим отступом, точный межстрочный интервал; вопрос с вариантами не разрывается (keepNext/keepLines).
- Раскладки: «несколько на листе» — таблица с пунктирными линиями отреза, ряд вариантов не разрывается (как образец: альбомный A4, поля 1 см, 2 колонки, 10 пт); «вариант на странице» — с новой страницы, колонки раздела.
- `Paginator` — модель раскладки Word; авто-выбор по реальному объёму текста: компактно, если вариант помещается в пол-альбомного листа; иначе самая удобная из (книжная 1 кол. 12/11 пт, книжная 2 кол. 11, альбомная 2 кол. 11, … 10 пт), при которой самый длинный вариант помещается на страницу; иначе плотная раскладка с продолжением.
- Предпросмотр = файл: текст меряется Liberation Serif (ширины букв совпадают с Times New Roman, проверено по таблицам шрифтов), без кернинга и хинтинга; учтено, что Word не ставит отступ перед абзацем в начале колонки. Сверено с LibreOffice: тест 2×5 — те же переносы строк; тест 40×30 — 83 страницы и в предпросмотре, и в LibreOffice, все варианты начинаются на тех же страницах.
- Экран «Файлы теста»: раскладка (режим, ориентация, колонки, шрифт 10–14, линии отреза, «как предлагает приложение»), страницы предпросмотра (нажатие — крупно, с масштабом), «Скачать тест», «Ответы» (системное «Сохранить»), «Отправить оба файла».
- Файл ответов: таблица «вариант × номер вопроса» (по 20 номеров в строке), номер верного ответа.
- Проверки на компьютере: `DocxExportTest` (метрики настоящего TNR), `PhoneDocxCheckTest` (файл с телефона в examples/check); шрифты Liberation (SIL OFL) в res/font, лицензия в licenses/.
